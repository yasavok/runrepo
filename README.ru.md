# runrepo

Запуск любого проекта одной командой. `rr` понимает, что за проект перед ним, показывает, чего не хватает, спрашивает, чинит и запускает.

[In English](README.md)

```
$ rr

shop  Node.js, next
  ✓ node 24.18.0
  + зависимости   не установлены
                → npm install
  + .env          нет файла, заполни потом: STRIPE_KEY
                → создать .env из .env.example
  + порт 3000     занят: python (15624)
                → взять порт 3001
  ! PostgreSQL    не отвечает на порту 5432
  ▶ npm run dev

Исправить и запустить? [Y/n]
```

## Установка

Нужен Node.js 20+. Зависимостей нет.

```
git clone https://github.com/yasavok/runrepo
cd runrepo
npm link
```

Дальше зайди в любой проект и набери `rr`. Если команда `rr` в системе уже занята, есть `runrepo`.

## Что проверяет

| Проверка | Что делает |
| --- | --- |
| Язык и версия | сверяет с `engines`, `.nvmrc`, `requires-python`, `go.mod`, целевой платформой |
| Зависимости | ставит тем менеджером пакетов, которым пользуется проект |
| `.env` | создаёт из примера, перечисляет недостающие ключи |
| Порт | называет программу, которая его заняла, и берёт соседний, если проект позволяет |
| База данных | находит локальные адреса в `.env` и поднимает сервис из `compose`, если он там есть |

Понимает Node.js, Python, .NET, Go, Rust, Java, PHP, Ruby, Docker Compose и обычный HTML. Находит папки `frontend` и `backend` и запускает вместе.

Если проект упал, `rr` объясняет причину простыми словами.

## Безопасность

- До твоего согласия ничего не меняется, `--check` не меняет ничего вообще.
- Чужие программы не завершает, готовый `.env` не перезаписывает.
- Значения из `.env` не показывает, только имена ключей.
- Установка и запуск выполняют код проекта, как и вручную. Не запускай то, чему не доверяешь.

Параметры: `rr --help`. Не понял твой проект? [Напиши](https://github.com/yasavok/runrepo/issues/new/choose).
